1. 采用“桌面优先，移动端降级”的适配方向
这个网站的核心魅力在于材质、粒子、大画幅地图——这些在桌面端才能完全展现。手机端我们追求信息清晰、操作顺滑、氛围不丢失，而不是像素级复刻。

2. 在设计组件时直接预留“双模”结构
时间轴：设计成 Flex 行，自带 overflow-x: auto，天然支持窄屏横向滑动，不需要改 DOM。

地图：Canvas 尺寸用百分比宽度配合固定纵横比（aspect-ratio），内部坐标投影函数根据实际画布大小动态计算，这样无论屏幕多大都能自适应。

粒子系统：粒子数量通过一个可传入的参数控制，初始化时检测窗口宽度，低于 768px 传入 150，否则 400。

玻璃拟态与滤镜：用 CSS 自定义属性（--blur-amount）控制模糊值，在媒体查询中将其设为 0 或降低。

3. 交互层从一开始就统一事件模型
用 Pointer Events 替代单独的 Mouse/Touch 事件，一个 pointerdown 就能覆盖所有设备。拖拽区域的尺寸在移动端适当放大（最小 48×48px 的触摸目标），这些尺寸同样用 CSS 变量控制。

4. 使用逻辑断点而非固定设备尺寸
不要只设一个 768px 断点。这个网站可能的断点需求：

> 1200px：大桌面，完整大画幅地图，多列履历卡片。

768px - 1200px：平板/小桌面，地图缩小，时间轴稍紧凑。

< 768px：手机，单列布局，地图简化，粒子减半，模糊关闭，时间轴可横滑，拖拽目标加大。

5. 双端互斥元素必须设置基线 display:none
桌面优先意味着桌面端样式是 CSS 的基线（无媒体查询包裹）。如果某个元素仅在移动端显示（如手机专用的信息流容器），必须在基线 CSS 中显式设置 `display: none`，然后在 `@media (max-width: 768px)` 中覆盖为 `display: flex/block`。反之，桌面端专用元素需在移动端媒体查询中设置 `display: none`。这是桌面优先策略最常见的遗漏点——不能让浏览器默认的 `display: block` 决定互斥元素的可见性。

阶段一：全局设计令牌与响应式锚点校准（地基层）
目标：让所有后续细节自动继承响应式行为，不用每次单独判断。

操作：

在 :root 中补全所有设计令牌：

色彩（每章的背景、文字、强调、阴影）

字体阶梯（--fs-title: clamp(2rem, 8vw, 4.5rem); 用 clamp() 锁定上下限）

间距尺度（8px 倍数系统）

动画参数（统一 ease 曲线和时长变量）

响应式敏感变量（--blur-amount, --particle-count, --map-width）

用媒体查询只覆盖这些变量，不改具体组件：

css
@media (max-width: 768px) {
  :root {
    --blur-amount: 0px;
    --particle-count: 150;
    --fs-title: 2rem;
  }
}
验证：在桌面和手机尺寸下，全局背景色、字体大小、间距是否已自动适应，无需滚动即可看出比例协调。

阶段二：组件静态度量与排版对齐（骨架层）
目标：所有元素的位置、大小、留白在任何屏幕上都稳定且舒适。

操作：

逐组件检查布局：主容器用 max-width + width: 90vw，内部用 Flex/Grid + 百分比/fr 单位。

固定宽高元素（如地图 Canvas）使用 aspect-ratio 或动态尺寸计算，配合 ResizeObserver。

每个组件的内边距、外边距全部引用间距变量，不写死数值。

时间轴、卡片网格等横向排列，在手机上启用 overflow-x: auto 或切换为单列。

文字行宽控制在 60-75 字符，用 max-width: 65ch 限制。

验证：用浏览器 DevTools 的响应式模式，逐个组件在不同宽度（375px、768px、1024px、1440px）下截图，检查是否有重叠、溢出或过疏过密。

阶段三：材质与纹理的响应式降级（肌理层）
目标：保证桌面端的丰富质感不变成移动端的性能杀手。

操作：

SVG 滤镜：给纸张纹理、扫描线等滤镜包裹一层 @media (min-width: 769px)，移动端直接使用纯色背景或静态 SVG 图案替代。

玻璃拟态：backdrop-filter 的模糊值引用 --blur-amount 变量，移动端自动归零，同时增加背景色的不透明度以保持可读性。

Canvas 粒子系统：粒子数量读取 --particle-count（通过 JS getComputedStyle），初始化时生效。

大型装饰元素（如叶脉装饰线）：在移动端改为水平放置或缩小透明度，避免挤占内容空间。

验证：在手机实机上滑动，确保无卡顿，且视觉氛围不因去除效果而显得空洞——必要时用更轻量的 CSS 渐变替代。

阶段四：交互动效的跨设备适配（行为层）
目标：手势自然，动效不拖沓，移动端的“拖拽”和“悬停”有合理替代。

操作：

统一使用 Pointer Events，将交互区域的最小尺寸设为 44×44px（移动端可触碰）。

拖拽操作在移动端增加“长按触发”或“点击选中后再拖拽”的提示，避免与页面滚动冲突。

Hover 效果在移动端转换为点击激活（用 :active 或 JS toggle）。

动画时长和位移距离用相对单位，避免大屏上太慢、小屏上太快。关键动画使用 prefers-reduced-motion 媒体查询提供关闭选项。

过渡转场（白屏、故障效果）在移动端简化为更短的淡入淡出，节省 GPU 资源。

验证：在真机上进行完整章节走查，确保每个互动都有明确的反馈，且无手势冲突。

阶段五：精细调色与微交互润色（抛光层）
目标：在响应式基础稳固后，进行最后的感官提升。

操作：

色彩微调：在真实设备上观察，修正因屏幕差异导致的色偏（尤其是暗部细节）。

阴影与层级：检查卡片、按钮的 box-shadow 在各背景上是否足够区分层次，移动端可适当减弱扩散范围。

微交互：添加 10-30ms 的按钮按压回弹、卡片悬停的 3D 倾斜（移动端可跳过）、加载状态的小动画。

字体渲染：微调 -webkit-font-smoothing 和 text-rendering，确保像素字体在移动端不走样。

最终走查清单：

所有拖拽/点击目标在手机上易于操作

地图在城市标记点是否可点按查看详情

时间轴在手机上滑动流畅，小人定位精准

文字对比度符合可读性标准

页面加载后无布局抖动

验证：在不同操作系统（iOS/Android）和浏览器（Safari/Chrome）上快速过一遍，发现问题回到对应阶段调整变量或组件，而不需要动结构。

## 桌面分档响应式策略（202609 更新，取代 §4 桌面端部分）

> 桌面端（>640px）不再依赖单断点，改用**分档 + 令牌钳制**体系。参数详见 `specs/responsive.md` §9（尺寸锁定规则同级）。

### 分档

| 档位 | 触发 | 策略 |
|------|------|------|
| S 压缩档 | 641–1280px | 保持 vw 比例 + 字号 0.9 + clamp 下限保护 |
| M 基线档 | 1281–1600px | 现状比例（1920×1080 主流全屏） |
| L 上限钳制档 | 1601–2400px | 面板 clamp 上限（display 560px / console 360px） |
| XL 居中收缩档 | >2400px | UI 容器 max-width 2200px 居中；地图中心系数 0.44 |
| H1 矮窗压缩 | max-height 700px | 内容区 8vh、经历时间线 22vh、弹窗头图 90px |
| H2 矮窗降级 | max-height 520px | 隐藏经历时间线与鼠标坐标 |

### 硬性规则

1. **桌面端组件宽/高一律走 `clamp(min, vw, max)` 或设计令牌**，禁止裸 vw/px（M 档基线值除外）
2. **移动端 gate 阈值为 640px**：≤640 视为手机竖屏区间，641–768 属于 S 档桌面压缩布局
3. **分档只覆盖 `:root` 变量**，组件 CSS 不写媒体查询（互斥显隐的 gate 规则除外）
4. 新增档位/调整参数：先改 `specs/responsive.md` §9 表 → 用户批准 → 再改 `tokens.css`
5. **验证矩阵**：1366×768 / 1920×1080（基线零差异）/ 2560×1440 / 3440×1440 / 半屏 960×1080 / 1280×560 矮窗 / 640 边界 gate 行为

### 字号规则（202609 v2 流式 Fluid Type）

1. **单一流式基准**：全部字号由 `--fs-base: clamp(13px, 0.68vw, 16px)` 按固定比率派生（`--fs-2xs~--fs-xl`），组件禁止固定 px
2. **视口连续缩放**：1920 基线 13px 正文；2560 大屏放大 ~23% 至 16px；>2560 由上限钳制（超宽屏视距不变，不再放大）
3. **窄屏保底不缩小**：≤1366 由下限兜底 13px——正文 <12px 伤阅读，小屏压缩交给布局（面板 clamp 宽度）而非字号
4. **风格化不碰层级**：换字体/视觉大小/字距走 `--font-*` / `--fs-adjust` / `--ls-*`，比率阶梯保持稳定；特殊风格需网格对齐时可在主题块覆盖单个 `--fs-*`

### 移动端方案（202609 启用，gate 退役）

1. **移动端为独立双文件**（`css/mobile.css` + `js/mobile.js`），只读共享数据（RESUME/md），不触碰桌面模块；弹窗逻辑抽为共享 `js/modal.js`
2. **双端互斥**：≤640px 显示移动端 UI、隐藏桌面层；>640px 反之，基线必须显式 `display:none`
3. **移动端无地图、无时间轴**：背景为主题纯色；阶段切换走底部圆点；经历时间线收进右上 ⋮ 抽屉
4. **移动端组件触控区 ≥44px**，视觉与热区分离（圆点 8px/44px 等）
5. 桌面端任何非数据改动不得改变移动端既有方案，反之亦然（互斥验证矩阵：390/414/640/641/1920）
