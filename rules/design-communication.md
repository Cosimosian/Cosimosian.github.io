## 一、先对齐：你的网站设计需求分类

基于之前的解耦架构，把所有设计需求分为 4 类，不同类的**传达时机、方式、落地成本**完全不同，你需要先把模糊的设计想法归类：



| 需求类型      | 定义                                        | 举例                                 |
| --------- | ----------------------------------------- | ---------------------------------- |
| **架构级规则** | 影响分层架构、核心交互逻辑的底层规则，决定后续代码结构，修改成本极高        | 时间轴阶段切换逻辑、主题切换方式、页面锚点结构、卡片 DOM 结构  |
| **视觉级细节** | 三套主题的色彩、材质、动效、表现效果，独立封装在 CSS 主题文件中，修改成本极低 | 南法主题的纸张纹理、街机主题的扫描线密度、AI 主题玻璃拟态模糊半径 |
| **交互级细节** | 拖拽、hover、阶段切换、触屏反馈的行为逻辑，独立封装在交互工具类中，修改成本低 | 拖拽游标吸附距离、阶段切换动画时长、移动端拖拽热区大小        |
| **内容级细节** | 履历文本、项目配图、标签、链接，独立存储在 JSON 数据文件中，修改成本为 0  | 补充园林项目效果图、修改 AI 项目技术标签、调整项目展示顺序    |

## 二、精准传达时机：对应当前 7 阶段开发流程

利用**高内聚低耦合**的架构特性，不同类型的需求，要在**对应开发阶段启动前**传达，不用一次性交齐所有设计细节，也不会影响开发进度：

### 🔴 必须提前锁定：架构级规则

**最佳传达时机**：「阶段 1：搭建基础工程架构」**启动前**（开发第一天就要确认）

**为什么不能延后**：架构层是所有模块的基础，后期修改需要重构文件夹、HTML 锚点、JS 交互逻辑，会导致之前的开发全部作废。

**需要提前确认的架构级设计规则清单**：



1. 时间轴基础交互规则：是否保留「拖拽小人切换阶段」的核心逻辑，是否需要补充点击跳转、阶段自动吸附功能；

2. 主题切换机制：是否采用「根节点`data-theme`属性全局切换」的标准规则；

3. 页面模块结构：是否固定「顶部空白 / 标题 + 中间内容区 + 底部时间轴」的布局结构；

4. 组件复用规则：履历卡片、标签、分割线是否需要在三套主题中保持统一布局结构；

5. 二级页预留规则：是否提前预留项目详情页的锚点、布局模板。

### 🟡 按需提前提交：视觉 / 交互级细节

**最佳传达时机**：对应主题 / 交互开发**启动前 1-2 天**，不用提前太久，避免参考素材丢失或想法变动



| 视觉 / 交互模块                                                     | 对应开发阶段            | 传达时机               |
| ------------------------------------------------------------- | ----------------- | ------------------ |
| 南法园林主题视觉                                                      | 阶段 2：封装三套 TA 视觉主题 | 阶段 1 完成后、阶段 2 启动前  |
| 千禧街机主题视觉                                                      | 阶段 2：封装三套 TA 视觉主题 | 园林主题开发完成后、街机主题开发前  |

| 时间轴拖拽交互                                                       | 阶段 4：开发核心时间轴交互逻辑  | 阶段 3 完成后、阶段 4 启动前  |
| 移动端适配降级规则                                                     | 阶段 6：优化移动端适配      | 阶段 5 完成后、阶段 6 启动前  |
| **为什么可以延后**：视觉主题、交互逻辑是独立封装模块，和布局、数据完全解耦，开发前提交设计需求，不会影响其他模块进度。 |                   |                    |

### 🟢 随时可提交：内容级细节

**最佳传达时机**：任意阶段，甚至上线后随时可以补充修改

**为什么无影响**：所有履历内容独立存储在`resume.json`文件中，不涉及 HTML/CSS/JS 代码修改，更新后刷新页面即可同步展示，完全不会影响开发架构。

## 三、精准传达方式：技术美术专属「标准化设计需求包」

你兼具审美和技术能力，不用只靠语言模糊描述，也不需要专业设计软件产出的完整设计稿，用**文字参数 + 参考素材 + 线框草图**组合的需求包，AI 可直接落地，开发过程中不会出现理解偏差。

### 1. 架构级规则传达：「线框草图 + 逻辑说明文字」

重点讲清**结构和交互流**，不用标注视觉细节，工具推荐 FigmaJam、PPT、手绘后拍照：



* 用线框模块标注页面布局结构，划分内容区、时间轴区、游标位置；

* 用箭头标注完整交互流：比如「拖拽游标→释放后自动吸附到阶段中点→触发主题切换→内容区淡入淡出更新」；

* 书面化补充规则细节：比如「时间轴分为 3 个等分区间，分别对应三个阶段，游标拖拽到区间内自动吸附」。

### 2. 视觉级细节传达：「风格参考 + 量化材质参数 + 情绪描述」

三套主题分别提交参考，直接对应落地到 CSS 变量里，避免模糊词汇，必须给出**可量化的技术参数**：

#### （1）风格参考素材

每个主题提供 3-5 个精准参考素材，拼接成一张参考图或 Pinterest 画板，明确指出要复刻的风格点：



* 南法园林主题：比如提供「南法乡村花园的午后照片」「旧园艺杂志的纸质纹理」「莫兰迪低饱和自然色调」，明确说明需要还原的质感；

* 千禧街机主题：比如提供「90 年代街机厅 CRT 显示器实拍图」「经典像素游戏界面」「街机摇杆阻尼反馈感」，说明要还原的视觉效果；

* AI 未来主题：比如提供「苹果官网磨砂玻璃效果」「金属拉丝质感」「低温冷色流光粒子交互图」，明确材质表现要求。

#### （2）量化材质参数

给 CSS 变量提供直接可用的数值，开发时无需再调色，示例格式：



```
【南法园林主题参数】

基础色温：午后3点柔光，绝对色感偏暖，不刺眼

色彩变量：

&#x20; \--color-bg: 旧纸张米白 #F5F0E6，叠加30%透明度的纸质纹理

&#x20; \--color-text: 深棕灰色 #3A3228，衬线字体，文字边缘稍柔化

&#x20; \--color-accent: 苔藓绿 #92A87C，低饱和莫兰迪色调

材质变量：

&#x20; \--texture-paper: 噪声比例15%的内联SVG纸质纹理

&#x20; \--card-border: 米白色边框，模糊半径2px

动效变量：

&#x20; \--transition-theme: 主题切换过渡时长0.8秒，缓动曲线ease-in-out
```

#### （3）情绪叙事描述

补充 1-2 句话说明叙事目的，让开发过程中保留风格一致性，比如：

> 「南法主题要还原『在花园树荫里翻旧杂志』的松弛感，光线是漫反射的，材质肌理是粗糙自然的，阴影过渡要非常柔和；街机主题要还原『老显示器通电后荧光粉发光』的视觉效果，扫描线是淡灰色半透明，边缘有轻微的几何失真；AI 主题要营造『低温金属上的凝露』科技感，玻璃拟态模糊半径 12px，有很细的高亮反光边。」

### 3. 交互级细节传达：「动作拆解 + 参数标注 + 移动端补充」

把模糊的交互想法拆解为**技术可落地的动作步骤**，标注参数，工具推荐手绘交互流或 Figma 做简单原型：

#### 示例：时间轴拖拽交互需求



```
【核心交互规则】

1\. 拖拽行为：鼠标按下/手指按住游标后，游标可左右拖动，移动过程中实时显示当前阶段的主题预览；

2\. 吸附逻辑：拖拽释放时，若游标距离阶段分割点的吸附区间小于50px，自动吸附到该阶段的中点；

3\. 触发时机：游标停止移动后，再触发主题切换和内容更新，避免频繁切换导致卡顿；

4\. 游标反馈：拖拽时游标放大1.2倍，添加下拉阴影效果，释放后还原；

【移动端适配补充】

1\. 拖拽热区大小：触控热区宽度扩大到80px，高度扩大到60px，避免误触；

2\. 拖拽灵敏度：移动端降低拖拽灵敏度，手指滑动距离与游标移动比例为1.5:1；

3\. 动效降级：拖拽时关闭游标放大效果，减少过度绘制消耗。
```

### 4. 内容级细节传达：「标准化内容清单 + 素材命名规范」

按阶段整理内容，直接复制到`resume.json`中即可渲染，不会出现资源路径错误、内容错乱等问题：



* 文本内容：按阶段整理标题、描述、项目标签，统一使用无格式纯文本；

* 素材资源：按阶段分文件夹命名，比如`garden-project1.jpg` `ai-project3.png`，统一压缩为 WebP 格式，保留原图作为兜底；

* 链接配置：外部链接、项目详情页链接统一整理在表格中，明确是否需要在新窗口打开。

## 五、避坑指南：避免设计传达偏差



1. **不要用模糊抽象词**：禁止使用「好看的颜色」「有质感的效果」「流畅的动画」这类描述，必须给出**量化参数**或**明确参考物**，比如「还原 iPhone14 Pro 官网的磨砂玻璃效果」「扫描线密度为每英寸 15px」；

2. **不要中途修改架构规则**：如果后期突然想改时间轴的交互规则、主题切换方式，需要重新评估架构改动成本，避免之前的开发成果作废；

3. **优先提供静态参考，不要只看动态视频**：视频的光线、运动效果很难复刻为 CSS/JS 代码，优先提供**静态高清参考图**，标注需要还原的光影、材质、色彩细节；

4. **和 AI 开发对话时，明确指定落地文件**：提需求时要说明「把南法主题的背景色参数落地到`garden.css`文件的`[data-theme="garden"]`变量中」，避免 AI 生成冗余、硬编码代码；

5. **提前调试移动端效果**：设计时要考虑到移动端的性能瓶颈，提前确定可以接受的降级效果，比如关闭纹理叠加、降低阴影模糊半径，避免后期移动端出现卡顿。

## 六、补充：AI 辅助开发时的设计校验技巧

你可以用 AI 先生成**设计预览代码**，确认效果后再正式开发，节省沟通成本：



1. 提交视觉需求后，让 AI 先生成**主题变量预览页**，展示三套主题的色彩、纹理、文字对比度，确认后再生成完整主题 CSS 文件；

2. 提交交互需求后，让 AI 先生成**时间轴交互原型**，只有拖拽交互逻辑和占位样式，确认拖拽灵敏度、吸附效果后，再接入完整业务逻辑；

3. 开发过程中，让 AI 在页面里预留**实时调试入口**，比如在控制台输入`setTheme('garden')`可以切换主题，输入`timeline.setSplitRatio([0.4,0.7])`可以修改阶段分割比例，实时调整参数并同步到源码中。

按照这个流程和标准传达需求，完全可以把你脑海里模糊的风格想象，精准转化为符合工程标准、具备视觉差异化的求职官网，网站本身也能同时证明你的审美设计能力和技术理解能力。
